# CS-320
Software Test
How can I ensure that my code, program, or software is functional and secure?
When I think about how to make sure my code, program, or software is functional and secure, I rely on testing as my first line of defense. Writing unit tests for each method helps me confirm that the code does what it is supposed to do and that new changes don’t break existing features. I also make sure to follow best practices like validating inputs, keeping code organized, and being careful about how data is stored or accessed. By building in testing and security considerations from the beginning, I feel more confident in the quality of my work.

How do I interpret user needs and incorporate them into a program?
Interpreting user needs is all about translating requirements into features that actually make sense in the program. For example, in the Contact Service project, the basic user needs were being able to add, update, and delete contacts. I took those needs and turned them into methods that could be tested and used in a real-world scenario. I also tried to think about how someone might use the program in practice, which meant making sure it handled errors and edge cases in a way that still supported what the user wanted.

How do I approach designing software?
When I approach designing software, I usually start by breaking down the requirements and figuring out the simplest way to structure the program. I use object-oriented principles so each class has a clear responsibility, and I design with testing in mind so I know the program can be validated later. Keeping things modular not only makes the program easier to build, but also easier to maintain and improve over time. Thinking about testing and design together has helped me write stronger code that actually works the way it is supposed to.
